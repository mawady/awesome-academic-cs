# Contributing

Suggestions and pull requests are welcome. Please read the guidelines below before submitting.

## Adding an entry

- Check that the resource is not already listed.
- The resource should be genuinely useful for academic teaching or research in computer science — prefer quality over quantity.
- Add the entry to the correct section in alphabetical order where possible.
- Use the existing format: `- [Name](url) — Brief, neutral description. \`License/Cost tag\``
- One entry per pull request makes review easier.
- If you are proposing a new section, include at least three entries for it.

## Removing or updating an entry

- If a link is broken or a tool is discontinued, open an issue or PR with a fix or removal.
- If a free tool has become paid (or vice versa), update the cost tag accordingly.

## Quality checklist

Before submitting a PR, confirm:

- [ ] The link works and points to the correct page.
- [ ] The description is neutral, concise (one sentence), and written in your own words.
- [ ] The cost/license tag is accurate (`Free`, `Freemium`, `Open Source`, `Commercial`).
- [ ] No duplicate entries exist.
- [ ] The PR title follows the pattern: `Add [Tool Name]` or `Fix [issue]`.

## What will not be accepted

- Self-promotion without clear academic utility.
- Affiliate or referral links.
- Resources that require registration just to browse.
- Entries without a description.

## Code of Conduct

Be respectful and constructive in all interactions.
